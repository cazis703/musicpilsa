# 타이핑 오버레이 UI 통합 + 오탈자 처리 개선 + 다시쓰기 버튼 — 작업 계획

## 배경
지금은 문장 표시 영역(글로우/파티클 이펙트가 있는 `<p>`)과 실제 입력창(`<input>`)이 위아래로 분리되어 있다.
타이핑웍스(typing.works)처럼 흐린 목표 문장 위에 입력한 글자가 그대로 겹쳐 보이는 방식으로 바꾼다.
예전에 이 방식을 시도했다가 "입력값 오차"가 나서 결국 지금처럼 분리했던 이력이 있음
(정확한 증상은 기억나지 않는다고 확인됨) — 가장 흔한 실패 원인들을 미리 방어하는 방식으로 설계한다.

## 핵심 기술 방식
1. 목표 문장(흐린 글자 + 타이핑된 글자의 글로우/파티클 효과)을 보여주는 레이어와,
   실제 타이핑을 받는 `<input>`을 같은 위치에 절대 위치(absolute)로 겹친다.
2. `<input>`의 글자 색상은 완전히 투명(`color: transparent`, `background: transparent`)하게 하고
   커서(caret)만 보이게 한다 (`caret-color`). 실제로 눈에 보이는 글자는 아래 글로우 레이어뿐이다.
3. 두 레이어(목표 문장 레이어, `<input>`)는 반드시 **폰트 종류/크기/자간/줄높이가 완전히 동일**해야
   글자 위치가 어긋나지 않는다 — 같은 CSS 클래스를 공유해서 값이 따로 놀지 않게 한다.

## 예전 실패를 되풀이하지 않기 위한 방어 포인트 (가장 흔한 원인 3가지)
- **가운데 정렬 밀림 방지**: 입력할수록 텍스트가 길어지며 `text-align: center`가 매번
  재정렬되어 목표 문장과 어긋나는 게 가장 흔한 원인. → 글자 레이어와 입력창 모두
  `text-align: left`로 고정하고, 전체 블록을 감싸는 바깥 컨테이너만 화면 중앙에 배치한다.
- **한글 조합(IME) 중 흔들림 방지**: 지금 판정 로직(`useSentenceTyping.handleInputValue`)은
  이미 "조합 중 자모"가 아니라 "커밋된 전체 문자열"만 비교하는 안전한 방식이라 그대로 재사용한다.
  다만 조합 중간 자모가 실제 DOM에 잠깐 보이는 것 자체는 막을 수 없으므로, 입력창 글자를
  투명하게 만들어 애초에 눈에 띄지 않게 한다.
- **폰트 렌더링 오차 방지**: 두 레이어에 서로 다른 컴포넌트/클래스를 쓰면 미세하게 다른 스타일이
  섞여 들어가기 쉬우므로, 폰트 관련 클래스를 한 곳(공용 상수/클래스)에서만 관리한다.

## 유지할 것
- 글자별 glow-in / settled / fading 효과와 파티클 캔버스는 그대로 유지 (오늘 확인 완료)
- IME 안전 비교 로직(`useSentenceTyping.ts`)은 변경 없음 — 렌더링 레이어만 바꾼다
- 오탈자 표시(`isTypo` 밑줄), Enter로 즉시 다음 문장 이동 등 기존 동작 동일 유지

## 변경 파일 (예상)
- `src/components/typing/SentenceTypingArea.tsx` — 입력창을 내부로 받아들여 오버레이 구조로 재작성
- `src/components/typing/HealingTypingScreen.tsx` — 기존 별도 `<input>` 제거, 위 컴포넌트로 통합
- `src/components/typing/TypingChar.tsx` — 필요 시 폰트/정렬 관련 클래스만 미세 조정 (효과 로직 변경 없음)
- 신규 공용 상수/클래스 (폰트 크기·자간·줄높이를 한 곳에서 관리)

## 검증 계획
1. typecheck 통과
2. 브라우저에서 실제로: 처음부터 끝까지 오차 없이 겹쳐지는지, 오탈자 시에도 밀리지 않는지,
   한글 조합 중에도 자연스러운지, 문장 길이가 길어져도(가장 긴 문장 기준) 깨지지 않는지 확인
   → 이 부분은 제가 터미널에서 확인 못 하므로 사용자 브라우저 확인이 필요함을 안내

## 추가 범위 A: 오탈자 처리 개선 (타이핑웍스 방식)

### 확정된 사양
- 오타는 최대 **5글자까지** 연속으로 입력 가능. 6번째 잘못된 키 입력은 아예 입력되지 않도록 막는다
  (지워야만 다시 입력 가능). 단, 문장 끝에 도달하면 5글자를 다 채우지 않았어도 그 이상은
  입력되지 않는다(문장 길이를 넘어서는 입력 자체를 막음).
- 오타 구간에는 **사용자가 실제로 입력한 글자**를 다른 색(빨간색 계열)으로 표시한다
  (목표 글자를 그대로 두고 색만 바꾸는 게 아니라, 실제 오타 글자 자체를 보여줌).
- 오타가 남아있는 동안에는: (1) 새 글자가 맞아도 글로우 시작 애니메이션이 없고,
  (2) 이미 진행 중이던 글로우→정착→페이드 애니메이션도 **일시정지**되어야 한다(글자가 사라지지 않음).
  오타를 지우면(백스페이스) 애니메이션이 다시 정상 진행된다.
- 오타 구간은 지우고 다시 쓸 수 있어야 한다(기존 백스페이스 동작 유지).

### 구현 시 고려사항
- **오타 5글자 강제 컷**: 지금 입력창은 비제어(uncontrolled) `<input>`이라 브라우저가 이미 6번째
  글자를 DOM에 넣어버린 뒤에야 우리가 알 수 있다. `onInput`에서 오타 길이가 5를 넘으면
  `event.currentTarget.value`를 5글자로 즉시 잘라내고 커서 위치도 그 끝으로 맞춰서
  "애초에 입력이 안 된 것"처럼 되돌린다.
- **오타가 목표 문장 길이를 넘어서는 경우**: 문장 끝을 넘어서는 입력은 아예 막는다(오타 허용 글자 수는
  "5글자"와 "문장에 남은 글자 수" 중 더 작은 값). 즉 문장 끝에 도달하면 오타 5글자를 다 채우지
  않았어도 그 이상은 입력되지 않는다 — 목표 문장 글자 슬롯 밖으로 넘어가는 별도 렌더링은 필요 없다.
- **애니메이션 일시정지**: 지금 `useCharEffects`는 `performance.now() - glowStartedAt`로 경과시간을
  계산하는데, 이 방식은 그대로 "멈췄다가 다시 재개"를 표현할 수 없다(멈춰있던 시간만큼 나중에
  갑자기 확 진행돼버림). 프레임 델타(delta)를 누적하는 방식으로 바꾸고, 오타가 있는 동안에는
  델타를 누적하지 않도록 한다.
- 판정 로직(`useSentenceTyping.ts`)과 시각 효과(`useCharEffects.ts`, `TypingChar.tsx`) 양쪽을
  같이 수정해야 하며, 위 오버레이 작업과 같은 파일들을 건드리므로 한 번에 같이 진행한다.

## 추가 범위 B: "다시쓰기"(현재 문장 리셋) 버튼

- 건너뛰기 버튼 근처에 배치 (같은 하단 컨트롤 줄).
- 클릭 시: 다음 문장으로 넘어가지 않고, **같은 문장**을 처음 상태로 초기화한다
  (charStates 전체 pending으로, 입력창 비우기, 커서 0으로).
- 단축키: **Esc**. 문장 입력 중 Esc를 누르면 즉시 리셋된다.
- 기존 버튼들과 동일하게 클릭음(playClickSound) 재생.
